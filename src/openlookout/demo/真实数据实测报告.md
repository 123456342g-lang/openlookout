# OpenLookout 真实开源数据实测报告

目标：用户拒绝等 1–2 周自己录数据。用**真实、可合法使用**的开源电脑使用痕迹，跑现有发现流水线，看「惊喜」是否还能在模拟题之外成立。

结论先说：**方向仍然成立，但惊喜会降级。**  
真实数据上，系统能稳定找出「窗口来回撕扯 / 跨应用搬运 / 反复盯同一文件」这类**用户自己未必会量化的摩擦**；但因为公开数据集几乎没有可验证的源表格与完整文件内容，卡片大多停在「已整理的观察草稿」，做不到模拟数据里那种「重算周报发现漏算 200 元」的硬核 wow。

## 3. 流水线改动（为真实数据补齐，不读 ground_truth）

在 `lookout/detectors.py` 增加了真实痕迹友好的通用规则：

1. **英文截止日**（`Deadline: 20 November 2023`）  
2. **跨 App 粘贴聚合**（标题碎片化时仍能按 app 对统计）  
3. **window_thrash**：短窗内两窗口高频切换  
4. **recurring_doc_focus**：多日反复打开同一归一化窗口且累计停留够长  

`real_data/run_real.py`：限制入选发现、判断员用 flash、缺源文件时退化为 observation 卡（不硬调 compose）。

### 4.1 RLKWiC p1（`runs/real_rlkwic_p1/`，演示页 `demo/inbox_real.html`）

检测器共 **38** 条；入选 7 条；判断员通过 6 条上卡。API：2 次 flash 调用。

| 卡 | 标题（节选） | 证据要点 |
|---|---|---|
| R2 | **5天切234次窗口，切换记录已整理** | 两份相关 PyCharm 脚本 `opt_loopbyloop_Networkx.py` ↔ `opt_optimization_engine_networkx.py` 5 天切 234 次 |
| R4 | **核心文件8天643分钟** | 几乎每天泡在 `opt_optimization_engine.py` |
| R1 | **9天67次跨应用搬运** | pycharm → msedge 粘贴 67 次 / 9 天 |
| R6 | **2天72次浏览器到Word** | msedge → winword 短时高强度 |
| R5 | 邮箱双窗口切 89 次 / 6 天 | 可能重复开窗对照（略弱） |
| R3 | Home - Ziggurat 4 天 253 分钟 | 定期回看 |

**漏掉 / 压低：**

- 特殊 Issue 表单里的 **Deadline: 20 November 2023** 被检出，但距「数据末日」还有 137 天 → 判断员正确标为不打扰。  
- 大量同项目脚本反复打开被多样性截断（每类最多 2 条），避免刷屏。  
- **没有**出现模拟数据里的：周报漏算、对照样漂移、账单重复扣费——公开数据里基本没有那种可对账的源表。

## 5. 和模拟 9/9 的对比（诚实）

| 维度 | 模拟林晓雨 | 真实 RLKWiC / AWT |
|---|---|---|
| 埋题可知 | 是（自己出题） | 否 |
| 可验证硬错误（漏算、漂移） | 有，且验过 | **基本没有**（缺源表） |
| 「用户未必注意到的摩擦」 | 有 | **有**（切换次数、粘贴密度、泡文件时长） |
| 卡片形态 | 多数「已做好并验证」 | 多数 **观察草稿**（observation_only） |
| 误报 / 噪声 | 模拟里干扰项被滤掉 | 真实里仍有邮箱双开、同名窗口等偏弱条；靠判断员与多样性截断压住 |
| 「惊喜」强度 | 高（发现你算错了） | **中**（发现你在无意识地苦干） |

一句话：**惊喜还在，但种类变了——从「纠错惊喜」变成「镜子惊喜」。**  
镜子仍然有产品价值（量化你没注意的摩擦），但还不够单独撑起「改变生活方式」的叙事；要回到模拟级 wow，需要带文件内容 + 可对账结构的真实录制（用户自己录几天即可，不必两周）。

## 6. 是否还值得做？

**值得继续**，理由：

1. 真实连续多日痕迹上，规则层能在**不偷看标注**的情况下找出可解释的摩擦模式。  
2. 判断员（flash）能压掉一部分「正常习惯」。  
3. 公开数据的缺口本身证明了产品设计：真正的 wow 依赖**本机文件 + 剪贴板 + 表单**，这些恰好是开源数据集稀缺、而用户本机才有的信号。

**不要过度宣称**：当前还不能说「在真实世界上已经复现了 9/9」。只能说「发现摩擦」这条腿在真实数据上站得住；「做好并验证解决办法」这条腿仍缺数据燃料。

---

## 7. 建议的下一步（不等两周）

按性价比排序：

1. **用户录 1 个工作日**（Windows 记录器 + 浏览器扩展已就绪）→ 用真实剪贴板/文件重跑；半天数据就够测 paste friction。  
2. **合成评测集（诚实标注）**：把公开 AWT/RLKWiC 的窗口流，配上从论文/开源仓库抽的真实表格作为「虚拟工作区」，专门测「发现 + 验证」——比干等录制快，又比纯模拟少作弊感。  
3. 继续丰富积木：对 `window_thrash` / 跨 App paste 给出「分屏提醒 / 导出模板」类轻量交付，让观察卡也能变成「已准备好的小动作」。  
4. 不做：继续只靠无文件的公开窗口日志硬冲验证级 wow——数据物理上不够。
