# 小精灵主动决策算法

VISTA 提供连续视觉上下文、回看与笔记，模型在同一会话中理解任务和对话。本地模块提供观测事实与工具，不按场景或计时决定是否开口。

## 在线循环

### 目标、证据与预期结果

本轮设计借鉴部分可观测决策和信息价值的思路，但没有实现经过训练的 POMDP 求解器。模型维护有证据的情境判断：用户希望得到的结果、当前阶段、与较长时间方向的关联、尚未解决的摩擦、注意力和兴趣假设。明确表达、行为推断和待验证解释分别记录；不知道的方向保持未知，不用主观精确分数掩盖不确定性。

候选包含观察、调查、帮助、后台准备、自然对话与等待。比较的是用户结果的预期改善，扣除行动、打扰和错误成本，并考虑验证假设的价值；不是按动作数量、指标下降或消息数量优化。能给后续工作打开局面的小进展可以优先，容易完成的维护不能自动优先。休息和关系也是用户结果的一部分，停留与短期低产出不能直接变成催促。

主动讨论、操作记录中的问题发现与帮助、后台维护共用同一个 VISTA 会话和判断，不按三层轮转。聊天可以与安静维护或准备发生在同一轮，聊天结束仍保留可执行的下一步。系统事实在初始观察中提供；主循环每 30 秒检查资源状态变化，压力出现时可以独立触发判断，不依赖翻页。没有新压力状态时不因数字抖动不断唤醒模型；每轮实际决策前重新读数，恢复后清除旧触发。这里只提供事实并唤醒判断，不自动按指标清理。长时间模型请求仍会阻塞主循环中的系统检查，当前版本尚不保证调查期间的即时维护响应。

WORKING 使用 VISTA 原生笔记，记录紧凑的目标与证据、待验证解释、候选与暂缓原因、下一步预期改善、核对方式和实际结果。阶段变化时重新审视，而非逐轮堆流水账。`companion.decision` 可携带内部依据，实际工具结果与最终决定写入本地 `perceive/decisions.jsonl`，quiet 也记录。可据此复盘选错目标、信息不足、时机过晚或执行无效；记录本身不是自动训练，也不是效果证明。

### 调查中持续观察

Windows 直连通道在独立采样线程中保留最新待处理画面，不在这里另造视觉历史。模型请求和工具调查期间仍每两秒采样；下一模型段通过原生 TaskRuntime 将新的 CURRENT 交给 VISTA，旧画面继续由 history 管理。变更操作和 offer 在画面更新后先返回工具错误，让模型重判；普通对话和 quiet 在切换前台窗口或收到用户新消息后重判，不因同一窗口中的每次像素变化禁止聊天。

同一窗口中的变化可能仍属于原目标，模型可以继续已有调查。同窗口快速翻页时，单段普通对话仍可能滞后，不能声称已消除所有过期发言；频繁切窗口也可能让决定持续重判。采样不中断正在等待的 HTTP 请求，实际反应延迟仍包含服务响应时间。容器通道本次没有接入段间现场更新。直连请求只保留当前和上一条普通用户话轮，工具调用/结果配对完整，较早画面由 VISTA history/inspect 回看；这会牺牲一部分模型传输上下文，换取不会随长期运行无限增长。纯文字、输出额度耗尽或没有正文的开口不能当成消息已送达，下一段只允许模型调用 companion 收尾。直连输出容量为 4096，是传输上限，不是聊天长度目标。

1. 从当前画面、历史画面、前台切换、停留时长、反馈和系统事实抽取证据。
2. 模型在 `WORKING.md` 中维护当前目标、阶段、阻塞、候选机会和待验证假设。
3. 每个候选带有证据强度、置信度、影响、紧迫性、阻塞解除度、信息增益、行动成本、打扰成本、可逆性和新颖度。
4. 模型结合证据、预期收益、信息增益、行动成本、打扰成本与可逆性进行判断；旧 `opportunity_policy.py` 的 UCB 风格评分保留作参考，当前运行时不调用它来决定开口。

5. 最高价值候选决定工作线：
   - `help`：解除当前目标阻塞，做一个最小可撤回动作并验证结果；
   - `maintenance`：后台修复或准备，默认安静；
   - `chat`：模型结合正在关注的内容、对话与认知负担判断是否自然接话，普通工作也可聊天。
6. 当前运行链路不再把 `opportunity_policy.py` 的规则评分作为开口闸门。帮助与聊天共用 VISTA 的语义判断，系统指标只作事实。

### 调查收敛与下一步

只读工具是取证手段，不是用户可见的进展。直连循环区分新的工具证据与重复结果：新资料允许继续调查，连续无新增证据的只读段才要求 `companion` 保存进展与下一步；后台阶段可以 quiet。达到段数上限时同样保留收尾请求，并额外给一次收尾机会。`next_step.ready` 自动续办，用真实工具证据修订号防止相同结果空转；同一动作取得新证据后可继续，不因历史上执行过一次就永久停住。仅换 evidence 描述不会绕过去重。`waiting` 写清外部缺口，`done` 表示该阶段完成，下一工作方向仍由模型判断。

## 主动聊天

`brain.py` 在调用模型前将实际送达的近期对话加入同一轮 CURRENT/history 上下文。模型自己选择切入点、是否查资料、说什么或保持安静。不限定场景，不设每日次数与聊天冷却，不由模板覆盖模型的 quiet。观察心跳用于重新判断和后台准备，不代表到点发消息。键鼠未动可能是在阅读或思考，不能直接解释为离开。

公共信息采集复用开源 DDGS 和 trafilatura，以 `basic_web_search` 和 `basic_web_read` 工具接入 VISTA。由模型选问题与来源，不能发送屏幕原文、私有路径、身份或密钥；天气与定位是可选工具，不是固定栏目。模型服务失败时不发送假装理解上下文的模板话。

检索以待验证的兴趣或实际目标为目的，不以画面中恰好出现的人名、日期和数字作为调研任务。搜索调用的 `purpose` 描述关联，`enough_when` 描述填补什么缺口即可回到对话；阅读调用也携带 `purpose`。这些依据不送给公共服务，只发送公共 query/URL。结果返回后模型对照原目的判断信息是否足够，而非不断追逐新枝节。无固定搜索次数或时间配额，复杂工作问题可以深入调查。

实际送达对话还提供“最近开口后是否收到接话”的上下文事实，没有回应不等于拒绝，也不能当成对小精灵选定话题的兴趣证据。初次开口只表达一个清楚、与关注点相关的小想法，用普通词让人不回查资料也听得懂；背景调查留在 VISTA 笔记，收到接话再展开。表达质量由模型语义判断，不能用截断长句代替提炼。

companion 对话使用独立的消息传递去重，只避免重复送出上一句，不以同一话题或时间窗口阻止继续交谈。实际变更提议继续使用原来的拒绝记录和执行边界。`intent=conversation` 区分交流与动作结果，后台内存维护的结果保持安静，但不会吞掉同轮的正常聊天。

Windows 直连模型通道将 VISTA 的 `inspect/history` 图片和引用标签一起返回模型。只返回工具文字会让模型拿不到历史画面、反复检查且无法收尾。每轮仍必须调用 companion 才能将安静或开口决定送到窗口。

`chat_planner.py`、`chat_facts.py` 是旧实验，仅保留作参考，当前 brain 不加载它们、旧预算、固定话术和每日生日信息。依赖安装：`python -m pip install -r requirements-proactive.txt`（在 `src/openlookout` 下运行）。定位使用开源 PyWinRT 调用 Windows 原生服务，需在系统设置中允许定位。

后台准备不再执行每日天气查询或按固定主题轮转；模型沿 WORKING 的目标和缺口自己选择准备工作。GUI 发送用户消息只保存原文，不立即生成“收到”或当前活动的模板回答；普通提问、观点和反馈统一进入模型语义理解。本地粗分类不决定回复内容。`next_step` 的 ready 会在后续事件中续办一次并去重；waiting/done 不制造空转回合。每个模型段记录输入/输出 token、缓存字段、请求大小、截图数和工具名，便于识别重复图片、读取笔记和调查枝节造成的浪费。当前直连服务的实际回放约 6–9k 输入 token/段，其中通常有约 4k 缓存命中；减少上下文不是简单截短，而是保留当前画面、待回应话轮、当前笔记和仍会改变决定的工具结果。

## 验收与能力缺口

### 自主查询操作历史

操作记录现在是直接输入，而不是只把查询工具摆在列表里。`HistoryFeed` 在来源实际更新时读取现有 backfill 与记录器日志，生成同一快照的跨来源小页，送入 VISTA 原生 INITIAL/STEP 环境文字；直连后续段保留当前记录上下文，避免换画面后丢失。每个来源先展示少量记录及覆盖、总量、未读页，数量是传输分页大小，不是行为或聊天配额；不预选作业名称、目标、日期和优先级。

监督进程复用根目录 `record_win.py` 记录窗口切换/停留、文件打开/保存等，输出到 `sprite_home/perceive/operations.jsonl`，与大脑/GUI 一起拉起，父进程退出后结束。没有开启剪贴板正文记录，也没有重做视觉历史。历史查询同时接入原记录器正在写入的 `data/events.jsonl` 与旧默认 `out/events.jsonl`；向模型只提供允许的事件字段，不传剪贴板正文和哈希。浏览器页面访问/下载继续从真实浏览器历史读取；扩展导航接收尚未接入这个新子进程，不冒称已采集完整页面交互。

`desktop_history` 的 activity 来源可按真实时间取 `events`、`order=asc`，观察一条线索前后发生的其他操作；`since/until` 筛选时间范围，不依赖同一关键词串。长 JSONL 每次从末尾读取最多 2MB，按完整行对齐，并返回每份日志的 `path/activity_next_before`。需要更早片段时以 `activity_before={path:字节游标}` 创建新快照，按绝对文件位置继续，即使日志仍在追加也不会追着末尾重读或丢失跨块事件。所有目标推断与取舍仍由同一 VISTA 会话分析，结果和反证写入 WORKING，未核实完成/困难/截止时间保持未知。

`desktop_history` 复用现有 Windows backfill 读取器，读取真实浏览器访问/下载、最近文件及 Office MRU；不使用调试人员导出的线索或注入候选作业。每次查询先取小页，稳定快照支持关键词筛选和分页，并返回来源覆盖与失败信息。`desktop_read_local` 沿实际路径核对目录、文本、docx 或 PDF 内容。历史属于环境事实，视觉上下文继续由 VISTA 管。模型自行判断查什么、候选目标是否未完成以及何时报告；操作时间不能当成截止日期，已有文件不能当成已完成。

调查线索与缺口写在 VISTA WORKING，现有笔记文件跨进程重启保存恢复；这是运行适配，不再建任务记忆库。提供这些工具不等于已经成功发现用户下一份作业：需要真实自主运行中的查询和取证结果验收。当前模型端点出现间歇 TLS EOF，传输仅对连接中断原样重试一次，证书校验与鉴权失败不重试、不绕过。

### 作业证据截图

每张截图围绕一个已核实的作业条目，明确参数、输入、输出、单位和上下文中哪些必须出现。`desktop_capture_evidence` 绑定最新 CURRENT 的 `source_id` 和实际图像尺寸；直连通道将此 id 随图片送给模型，inspect 放大后的坐标需映射回 CURRENT 原图。保存时核对原图与新采集画面、目标区域的差异，前台或画面改变则重新定位。原生分辨率 PNG 保留证据细节，不固定 1280x800 比例，也不按面积上限裁去必要内容。

工具返回裁图本身，由 VISTA 保存并回传给模型；新图初始为 `unreviewed`。模型看图后用 `desktop_review_evidence` 分别记录相关、完整、清晰、聚焦和实际依据，任何一项不满足即 `rejected`，不得据此宣称作业完成。通过后标 `accepted`，这是模型的视觉判断，尚未验证其在真实课程上的准确率。文件与元数据保存前写撤回日志；截图哈希变化后旧核验失效，撤回保留被修改过的文件。测试覆盖非 16:10 屏幕映射、目标画面变化、截后图像经 VISTA 返回、缺单位时拒用截图。浏览器实验执行与报告生成尚未接入，本次不将截图工具等同于整套作业自动完成。

### 对话话轮关联

用户直接消息分配稳定 id，模型通过 `companion.reply_to` 指明真实回应了哪条消息；发布、GUI 送达与持久化均保留此字段。模板确认不视为回答，未关联的主动开场也不会消除新消息的待回应状态。旧版无 id 的记录仅采用历史兼容判断，不能追溯验证旧回答的语义质量。当前待回应话轮显式进入模型上下文，旧对话标为背景，避免数小时后重复补答和绕回自己的观点。

普通对话优先接住当前意思，不要求先做战略扫描、读整份笔记或检索；修复日志和自我复盘不是主动谈资。关联到仍待回应消息的直接回复不因用户换窗口重来，但收到新用户消息仍需重判。场景触发的主动发言和电脑变更保留原有现场核对。

`python -m vista.benchmarks.desktop.replay_conversation` 用同一供应商、同一 VISTA 工具链回放合成的分歧和追问，输出实际回复、关联与时长。回放只保存到本地独立目录，不发布真实气泡，不使用真实屏幕或执行桌面动作。这检验对话表现，不能代表所有场景已自然，也不会消除供应商的响应延迟。

工程回归检查现场切换后旧动作未执行、新图经 VISTA 进入下一模型请求、普通消息未被伪回复、内部决策证据不出现在气泡、工具消息配对完整。它们验证链路，不验证模型已经有战略能力。

真实使用需要分别核对：正常推进但内存偏高时不制造任务；读书时能短而相关地接话；用户问理由时回答原问题；调查中转任务后不发布过期结论；连续返工时提出有证据的下一步；没有回应时不追逐自己引入的枝节。比较预期改善与实际结果，而不是以开口或工具调用作为成功。

现有动作能力集中在资源维护、桌面整理、诊断和公共资料。文档修改、办公流程及复杂工作执行尚缺工具，不能靠决策提示词冒充已经具备。需要沿真实高价值任务接入可核对结果的动作，再评估长期收益。直连仍使用有界传输消息窗口，本次没有实现完整模型上下文压缩；视觉历史与笔记仍由 VISTA 保存，长期语义连续性需要单独验证。

磁盘危急时 `desktop_reclaim` 不把模型传入的批量数字当作完成条件，而是继续扫描到安全候选耗尽；空间恢复后才允许非危急调用使用显式小批量。`max_items` 不设人为最大值，在危急状态下直接忽略，避免模型随手填的小数字中断解决过程。每个文件仍逐个经过 safe 风险分类、状态复核、撤回日志和隔离压缩校验，用户文件与不确定项不进入计划。2026-10-12 实机曾因模型使用 30 个上限只释放约 9MB，随后同一工具扩大到 200 个并释放约 1.29GB，全部可还原；后续已改为危急状态持续穷尽候选。

### 调查期间的上下文连续性

2026-10-12 启动审计：上一完整会话执行了 55 次目录关键词搜索、6 次本地读取，但没有调用操作历史工具。它能沿现有开发线深入调查，却没有比较未读取的真实历史来源；旧 WORKING 的目标与当前前台造成锚定，不能将它解释为历史中没有作业。目录搜索还把 query、scanned 等请求元数据计入新证据指纹，更换关键词得到相同空结果会重置无进展检测。

现在从本次会话真实工具返回生成紧凑取证覆盖：目录及空结果/截断次数、历史实际读取页数与最近页的来源覆盖、过滤词及未读页、本地读取数量。它属于现有传输上下文的执行事实，不是新记忆库，也不挑选具体任务。未查来源保持未知，目录匹配不冒充历史覆盖；模型依据信息缺口和预期价值决定下一步。目录搜索的新证据只取实际结果、范围与完整性，换词/扫描计数变化不会伪装成进展。这个修复针对调查空转，不保证模型一定选对任务；缺少浏览器实验和报告写入工具也仍是执行能力缺口。

直连通道记录真实决策轮的起点，现场更新与收尾提示不会另开传输轮。本轮已经取得的工具结果及调用配对保留到决策结束，避免画面不断变化时遗忘取证结果；旧轮次仍使用有限传输窗口。仅保留最近画面的原始图片，旧视觉依然通过 VISTA history/inspect 回看，不建立第二份视觉记忆。当前 WORKING 在 GUIDE 前完整传递，每段读取最新原生笔记；笔记作为环境输入提供，不插入模型自己的回答中。

重复失败动作与无新证据的只读调查都会进入收尾判断，保留失败结果和下一步，不能把被拒调用当成维护完成。连接被远端无响应关闭时原样重试一次，与 TLS EOF 相同；这不保证供应商响应及时。自主历史归并和上下文修复已经接线，但尚无用户下一份作业被正确识别的验收证据，维护成功也必须以真实执行结果核对。

## 合法的算法学习边界

REA 可用于分析拥有授权的本地程序、公开样例和兼容许可代码。对闭源产品，允许的路径是官方文档、论文、专利、公开案例和授权黑盒实验；实现必须由 OpenLookout 独立编写，不能复制受保护的实现或绕过许可。
## 开放探索与执行进度（2026-10-12 修正）

队列不能发现未知问题，也不能决定问题是否值得解决。已移除 brain 中固定的磁盘、内存、历史和聊天候选，以及只追一个目标的 GoalController。`agenda.py` 仅保存任意目标的执行状态、依赖、等待条件与结果引用；它不替代 VISTA 的视觉记忆、WORKING 或模型推理。

### 探索形成目标，而非目标清单驱动探索

1. 从实际操作片段、连续画面和环境事实识别值得解释的线索；一开始可以只有问题，没有确定的任务和解法。缺少记录与记录证明没有问题是两件事。
2. 区分观察事实、用户可能想得到的结果和待验证解释。有歧义时保留不同解释；用原生 WORKING 紧凑记录依据和反证，不为每一种场景建立专用模块。
3. 选择能改变下一决定的探查：预先考虑可能的返回、支持或推翻哪种解释，以及分别会改变哪项行动。只读工具可直接调用，不要求先注册目标，不受目标评分或变更次数限制。
4. 收到结果后对照预期，继续、排除解释、换方案、拆分或重定目标。信息足够时执行可核验的小行动；无改善时修正解释和方案，不能把重复原样动作当进展。
5. 自行还能取得关键证据就继续原生工具循环；真正缺外部条件才挂起该方向，比较其他机会。聊天、安静和某一目标等待均不清空其他执行进度。

这个流程借鉴主动信息获取和部分可观测决策。信息价值的理想定义是：探查结果到来后最优行动的期望效用，减去不探查时的最优效用，再减探查成本。资料新颖、返回字数多或降低了与用户无关的不确定性，并不自动有价值。项目目前没有经过校准的信念分布、效用模型或 POMDP 求解器，因此不把模型填写的数字当作这个理想定义的精确计算。

### 执行状态的实际约束

`desktop_plan` 增量更新目标，未提交目标保留。`decision_engine.py` 的手工权重仅产生 `suggested` 比较建议，不能强迫模型沿旧方向执行，也不能阻止新的只读探索。信息收益与探索奖励须关联下游决策价值，不再因新颖度本身加分。策略估计和目标级结果统计未经校准，不能据此声称已具备战略判断或自动学习算法。

变更前登记真实工具、参数、证据、预期与独立只读核验。实际调用精确关联登记步骤；多个目标的同一动作有歧义时先澄清归因，不将整轮工具结果都归功某个候选。变更后进入核验，工具异常保留“结果未确认”，不宣称没有改动；进程中断后先核验，不重放不确定变更。

完成需要引用本目标成功结果的 `result_id`，并填写 `assessment` 解释预期是否满足。变更必须有单独核验结果；只读调查可以依据其实际返回作出判断，无需为形式重复读取。assessment 是模型判断，协议只能要求它提供依据，不能自动证明语义正确。失败或其他目标的结果不能用来完成本目标。相同动作与相同已登记证据不能直接再次 ready，需改方案或获得新证据；这项结构去重尚不能识别所有换措辞的伪新证据。

执行状态变化可触发下一轮，不依赖页面变化。等待只暂停对应目标；没有新增状态的 ready 不会无限刷相同轮次，仍由既有现场事件、续办机制和心跳重新判断。单轮传输容量与无进展收尾仍存在，不是探索目标数量上限；HTTP 阻塞期间仍无法保证即时执行其他任务。

### 验收标准与依据

有效验收应使用未在代码中列出的工作流程，且不在输入中告诉模型隐藏问题的答案：检查它是否自主发现线索、取到区分解释的证据、因反证改目标、执行有效帮助并独立核对；同时检查无问题的对照场景是否制造任务。流程测试验证状态和归因，不能代替这项真实能力验收。

本次工程回归覆盖任意领域目标、只读自由探索、反证后修订、等待让路、独立结果归因、异常和重启核验、完成依据以及不奖励无关研究。当前浏览器实验、原文件编辑及完整办公流程仍未提供，不能因此声称未知办公场景均已解决。

### 从发现到真实交付的盲测

2026-10-12 增加 `replay_openworld`：同一个供应商模型、VISTA runtime 和真实本地读写、计算、执行登记，只有操作历史替换成隔离样本。输入不提供隐藏错误、任务名称或直接用户指令；空白画面下沿打开和保存记录自行读材料、比较差异并交付。结果、工具事件、核对表和撤回记录保存在 `sprite_home/openworld_replay/`，不发布到真实聊天窗口。

金额样本自主发现支架 12×37.5 应为450、导出375，合计应为641、导出566；生成金额差异核对表并独立读回，在一个判断轮内完成，约59秒。另一测量样本自主发现 24000mm³ 被错误标成24000cm³，正确是24cm³，生成逐行换算表、读回并完成登记，约86秒。无错误金额对照复算后一轮安静，没有创建重复成果。它们只证明两个受控工作流程的发现与交付能力，未证明已发现真实下一份作业、任意复杂场景成功或即时反应。

早期回放暴露了真实空转：计划重复长正文、来源相对与绝对路径不一致、读取额外 `limit` 导致核验结果无法归因、完成仍要求重复全目标、结果末尾请求用户许可。现在计划只登记交付文件名和来源，正文在写工具传一次；参数不匹配返回具体已登记步骤；核验允许改变未指定的读取长度，但文件与偏移必须对应；完成采用 `result_id` 与 `assessment` 增量。`next_step.ready` 需要实际工具与可调用参数，不能把未提供的编辑能力当作下一步。

验收按实际工具成功结果核对独立读回全文、目标完成和逐行数值，不以调用次数或正文中出现正确数字为通过。Markdown 中“总计/三行合计”均可表达同一合计项；金额回放最初被验收器误判为缺少“总计”标签，核对实际内容后修正这处格式误判。语义列含义和用户价值仍需要真实场景评估。

常驻会话初次缺乏目标且没有直接待回复消息时，先读取真实历史小页，不指定该找什么。后续由 VISTA 自由探查、比较解释与取证；这是一项覆盖缺口修补，不能代替战略理解。统计异常低也不能排除重复劳动、未解决目标或自然交流机会。

### 当前通用行动能力

`desktop_browser_inventory` 和 `desktop_browser_observe` 复用 Tabbit，盘点现有标签并观察指定页面；不导航、点击、填表或提交。pending 读取原 receipt，不重放；成功后 finish 释放任务并保留用户标签。浏览器实验尚未接入。

`desktop_write_deliverable` 可在小精灵自己的 deliverables 目录新建 md/txt/csv，不覆盖用户原文件，保存前记撤回日志与哈希、来源；模型须再独立读回确认。撤回只处理未被用户修改的自身交付文件。复杂 Word/PDF 报告、原文件编辑以及网站实验自动执行仍是明确能力缺口。

### 插件辅助的连续性修复（2026-10-12）

使用 Superpowers 的根因复现、先失败后修复与独立只读复审，修复三处执行断点：续办身份依据实际 tool/arguments，不再依据措辞；HistoryFeed 对已采集记录和覆盖判定变化，内容未变且游标有效时保留分页快照，快照被其他查询淘汰时即使来源未变也重新发布；开放机会探查记录实际对应的历史上下文，旧快照续读不能消耗新上下文的探查机会。没有增加视觉记忆、场景白名单或固定探索任务数。

严格分页回放不替模型补缺失 snapshot。金额问题样本在105.8秒内从后续记录找到差额75，生成核对表、独立读回并完成目标；另一测量样本在77.4秒内找到单位1000倍差异并交付核对表。正常金额对照最初出现无价值的“核对正常”汇报，定位到气泡指令与quiet政策冲突；限定为先判断用户可见价值后，新的对照41.5秒完成核对，没有开口或重复交付文件。单次受控结果不能保证所有场景自然或实时；真实下一份作业仍未验证。

Qodo 后续已登录，CLI 实测版本1.4.0；当前本地仓库没有 origin，账户代码库检索 OpenLookout 与 OpenLook 都为空，review 返回无法确定仓库，远程审查未启动。未伪造远程仓库或推送代码。常驻会话已热更新并继续取证，工具调用本身不计作已解决用户问题。详见根目录 docs/superpowers/specs/2026-10-12-autonomous-continuity-design.md 与对应 plans。

随后实测模型输入17k–29k，发现执行状态既在INITIAL/STEP公开文本末尾保存，又在每段请求追加，导致重复与陈旧快照。直连在保存公开文本时仅剥离与当时agenda.context完全匹配的末尾，原观察、对话和工具证据保留，每段统一附最新执行状态；容器公开文本不变。model_usage新增execution_context_copies，热更新后的实际8段请求均为1份，不用截断用户工作细节冒充上下文压缩。总token仍随真实取证增长，未声称所有浪费或延迟已解决。当前真实调查仍出现屏幕变化阻止basic_shell执行；通用shell有环境副作用，不能仅按模型声称只读就放过现场检查，尚需具体执行能力和场景相关性的可靠判定。
