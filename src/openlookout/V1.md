# OpenLookout V1 · 唯一核心功能

> 安装后约 10 分钟内，从本机已有历史痕迹里，挖出至少 1 个你自己说不出、也没察觉的需求，并交出一个在本机验证过、能直接用的方案。

## 一句话

**从可量化的行为痕迹里，发现用户无法用语言表达、也尚未察觉的需求，并交付已验证的解。**
行为负责定位「你是谁、卡在哪」；**已核对的外部趋势/新技术**负责打开「现在能做成什么」——两者交叉才出卡。

不是整理信息，不是代办体力活，不是空想头脑风暴，不是新闻/比赛订阅，不是创业点子机。

## 验收（Acceptance）

1. **Day-1**：用 `backfill_win` 回填历史即可，不必先录几天；目标约 10 分钟内看到第一张有价值的卡。
2. **卡片三件套**：每张卡必须同时有
   - **行为证据**（带数字的痕迹）
   - **可量化主指标**（metric）
   - **已验证成品**（artifact 路径 + 验证记录）
   - **优先**附带已核对趋势（url + date + opens）；纯新闻无行为 → 不出卡
   缺前三则不出卡。
3. **每日最多 3 张**；**惊喜门控**丢掉「早就能想到 / 只是提醒 / 只是观察」的发现；用户标「不重要」的写入 `feedback_rules.json` 降权（如考勤）。
4. **原始数据不出本机**；只有脱敏摘要才可选用云端模型（`--no-llm` 可完全本地）。

## 惊喜门控（摘要）

详见 `lookout/SURPRISE.md`。硬拒绝提醒类、观察类、世界雷达/机会引擎；要求潜在不一致信号 + 惊喜分 ≥ 0.35。

## 明确不做（NON-goals）

| 不做 | 为什么 |
|---|---|
| 新闻 / 比赛 / 安全公告摘要 | 定时机器人就能做，不是潜在需求 |
| 创业赛道 / 外部机会引擎 | 在找别人；V1 的用户就是安装者自己 |
| Agent 账本 / 多工具切换税产品化 | 工程卫生，不是改变生活方式的卖点 |
| 鼠标操控 / 自动发邮件付款 | 超出「已验证方案交给用户决定」 |
| 只提醒、不交付 | 会造成软件提醒式骚扰 |
| 大而全助手 | 一眼说不清场景，丢失核心 |

已隔离模块：`lookout/world.py`、`lookout/opportunity_engine.py`（见 `lookout/quarantine/`）。

## 怎么跑

```bash
# Windows 上回填（用户本机，需批准；含浏览器/最近/Office/文件/编辑器/git）
python backfill_win.py --days 90 --roots E:\ --with-content

# 在本仓库分析（盒内或 WSL）
python3 -m lookout.v1 --capture /path/to/backfill --out /path/to/out --no-llm --screenshot
python3 -m lookout.v1 --capture /path/to/backfill --out /path/to/out --no-llm --ablation  # 少源 vs 全源
# 产出：v1_inbox.html / v1_cards.json / gate.json / artifacts/；消融见 ablation.md
```

## 成功长什么样

用户看到卡时会愣一下：「我一直以为汇总是对的 / final 就是最新的 / 交作业很正常」，然后发现成品已经做好、数字对得上。  
如果只是「你每周五交周报」——门控应拒绝。
