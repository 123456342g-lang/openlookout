# OpenLookout 小精灵 (sprite)

像创业搭档一样陪你做产品：在后台持续观察，能安全、可撤销地顺手解决的小麻烦就做，**做完会自然地告诉你**；会主动问你在忙什么、提出帮忙；在真正的岔路口会基于证据提出质疑。它**听所有人的意见，但有自己的判断**：你的话、外部的看法、目标文件都只是证据，不是命令。没有待办清单，没有输入框。

## 用法（Windows，Python 3.11+，仅标准库；Linux 需 python3-tk）
```
双击 sprite\run_sprite.bat       # 右下角像素猫 + 气泡
python -m sprite --no-gui        # 只在控制台说话
python -m sprite --list          # 列出它做过的事
python -m sprite --undo ID       # 撤销某件事
python -m sprite --say 项目名 "这个很有前景"   # 告诉它你的看法（只作为证据记录）
python -m sprite --kill / --resume              # 紧急开关
python -m sprite.sim [--llm]     # 多日模拟（见下）
python -m pytest sprite -q       # 无头测试
```
数据目录 `%LOCALAPPDATA%\OpenLookoutSprite\`（`SPRITE_HOME` 可改）：`config.json`、`behavior.jsonl`（行为流）、`goals.txt`（你写的目标，每行一组关键词）、`messages.jsonl`（它说过的话）、`decisions.jsonl`（每次“说/不说”的打分与理由）、`judgments.jsonl`（它与你意见不同时的判断、置信度、证据）、`journals/`（撤销日志）。全部本地。

## 整体逻辑（不是规则/定时器）
1. **情境模型**（situation.py）：从行为流持续估计：你现在大概在做什么（焦点项目）、是否在心流/在场、今天投入、来回切换和放弃的次数、与目标的吻合度（“我不确定你在做什么”的不确定度）、每个项目的**自己的判断**（推进中/停滞/不清楚 + 置信度 + 证据）。
2. **统一决策**（decide.py）：汇报、关心、提议帮忙、岔路口挑战、不同意、坚持、改口，都是同一套“话题候选 → 价值 v”；开口有代价（心流中、静默时段、刚说过话、上一句没回应、不在电脑前）；还有**关系预算**：你接话上升，关掉/不理下降，缓慢恢复。净收益=v×(0.5+0.5×预算)−代价，高于门槛才说。每一步的候选分数和理由写入 `decisions.jsonl`。
3. **嗓子**（voice.py）：把“话题+证据”变成一句短话。可选 MiMo（`config.json` 里 `"voice_llm": true`；密钥只读 `~/.config/ai-butler/mimo.env`，不打印；只发脱敏事实，项目名换成“项目A”），不可用或输出不合格就退回本地措辞。
4. **有自己的判断**：
   - 你说“很有前景”，但证据是投入翻倍、成果为零 → 它会礼貌地说“我不太同意”，给出判断、把握（置信度）和关键证据，决定留给你。
   - 你重申而证据没变 → 只再表态一次，并说明什么新证据会让它改口；之后不再唠叨。
   - 外部意见（导师、文章，`source=outside`）同样只是证据。
   - 只有新证据（成果出现）才会让它改口，并明说“这次是你对”。你的话本身不会改变判断。
5. **安全动作**（core.py + catalog.py）：编号目录补齐结构、下载去重（只移动不删除）、重复报告版本化。只有新建/移动/复制/写新文件，不删除、不出监控目录、不覆盖、不联网、不发送/付款/提交；先 dry-run 再应用并写撤销日志，事后校验字节一致，失败回滚；文件 60 秒内改动过不碰。做完后是否、何时、怎么说，由上面的统一决策决定（比如你在心流里就先不说）。气泡上有“撤销”。
6. 静默时段（默认 23:00–08:00）、每日动手上限 5 次、`KILL` 开关仍然有效。

## 气泡与形象（gui.py / pixels.py）
青色像素猫四种状态：idle（眨眼）、observing（左右张望）、working（^ ^ 专注+火花）、thinking（睁大眼+思考点，有话要说）。气泡紧贴在精灵身边，尾巴指向精灵，靠近屏幕左缘时放到右边；只有一行到两行话 + 2~3 个小按钮（或“撤销/好”），没有输入框；自动消失（带选项的留更久，超时视为没理它，预算下降）；可拖动，位置记在 `sprite_pos.json`。截图见 `demo_private/sprite_states.png`。

## 模拟与诚实的局限
`python -m sprite.sim` 跑 7 段多日脚本历史（不安（乐观但停滞）→新证据、更好的路、两个对照、外部意见冲突、汇报做过的事、用户全都关掉）。结果与对话在 `demo_private/sprite_sim.md`（本地措辞）和 `sprite_sim_llm.md`（MiMo 措辞）。
- 对照组（高产且认同、分散低投入）：没有任何挑战/不同意/提议帮忙；分散低投入的对照里它约每 2.5 天问一次“你在忙什么”（34 天 13 次），这是不确定度驱动的关心，偏多。
- 仍有机械感的地方：价值函数的系数和门槛是手调的；“判断”是简单的投入/成果比较；话题仍是有限的几类；本地措辞库有限；行为流目前只能自动产生“文件改动=投入”，**成果、放弃、来回切换、更好的路径事件需要 recorder/用户标记来产生**，真实机器上这部分还没接。
- 未在真实 Windows 上跑过 GUI（只在 xvfb 下渲染验证）；tkinter 无抗锯齿，用整数倍放大的像素风和硬边气泡保持风格一致。

# 通用“发现问题→判断→行动”框架（framework.py）

电脑卡、磁盘满、桌面乱、日志暴涨……都不是写死的功能，而是同一个循环：

1. **观察状态变化**：系统探针（内存/磁盘/进程）和文件监控提供状态；检测器按阈值、变化速率、迟滞做**边沿触发**（只在“变糟”那一刻触发一次，持续危急不重复），没有定时清理任务。
2. **识别问题 `Problem`**：种类、严重度、证据、需要缓解多少。
3. **从动作库列候选 `Action`**：每个动作都带类型化的 `risk`(safe/medium/high)、`reversible`(full/partial/none)、影响范围（项数、字节）、预计缓解量，以及 `dry_run / run / verify / undo`。
4. **自己判断（Judge）**：
   - high 或不能完全还原 → 永不自动做，也不当成提议；
   - safe + 完全可逆 + dry-run 通过 + 范围不超限 + 这类动作的信任度够 → **自动做**，做完 `verify`，不过就回滚；够缓解问题就停手，不多做；
   - 只有“自动处理后仍没缓解够”的 medium 项，才合成**一个**问题问你，并给出建议；
5. **汇报**：交给原有的“说不说”决策核心（`decide.py`）：汇报做了什么（带撤销）或问那一个问题，受心流、静默、关系预算约束。
6. **从结果里学（Ledger）**：每类动作记 成功/失败/被你撤销 次数；被撤销 2 次降级为“要问”，3 次停用。
7. 所有判断写进 `judgments_actions.jsonl`（做了什么、跳过了什么、为什么）。

## 怎么加一个新场景（只注册，不改核心）
```python
from sprite.framework import Scenario, Problem, Action
def detect(world):            # 状态 -> [Problem]；自己做边沿触发
    ...
def propose(problem, world):  # 问题 -> [Action]；每个 Action 声明 risk/reversible/blast，并给出 dry_run/run/verify/undo
    ...
registry.register(Scenario("我的场景", detect, propose, group_text=None))
```
`scenarios/extras.py` 里有两个只靠注册加入的小场景（日志暴涨→压缩进隔离区；桌面堆积→按类型归档并写还原映射），核心一行没改；`test_framework.py::test_new_scenario_by_registration_only` 验证了它们可撤销、且不碰正在写入/刚改过的文件。

# 内存/磁盘压力场景（scenarios/resource.py，已端到端演示）
- **风险模型（risk.py）**：
  - safe：浏览器/包管理器缓存、超过一天的临时文件、`__pycache__/*.pyc`、有 https 来源的旧安装包、空闲很久的浏览器后台标签进程（**挂起，不是杀掉**，你切回浏览器时自动恢复）、父进程已退出的残留辅助进程；
  - medium：查不到来源的旧安装包、有逐字节核对过副本的大旧文件 → 只在自动处理后还不够时，合成一个问题问你；
  - high：用户文档、两小时内改过的、被占用/锁文件、路径含“最终/备份/论文/合同”、符号链接、前台窗口、正在播放、标题有 `*`/未保存的窗口、编辑器、有子进程的进程、正在被进程使用的 `node_modules`、任何“不认识”的东西——**一律不碰，也不提议删除**。
  - 叫 `cache/temp` 的用户文件夹、缓存目录里混进的 `.csv/.docx/.xlsx` 等，一律按 high。
- **动作机制**：不删除。文件进“隔离区”（同盘则先 zip 压缩并校验，才移走原文件；跨盘先复制并校验哈希），有还原映射，还原时从不覆盖已有文件、并校验哈希；动手前对每个文件**重新核对**（防止规划后又被你改了）。进程只挂起并收缩工作集，状态驱动恢复。
- **汇报**：先说做了什么，再问那一个问题（如有），例如：“我先暂停了 4 个闲置后台进程、清理了 16 个缓存/临时文件。电脑还有点卡，这几样我不敢替你定：old_dataset.bin（700MB）；Setup-2.exe（80MB）。建议先放隔离区（可还原），行吗？”
- **评测**：`python -m sprite.eval_risk` 生成 166 个带标签的对抗案例（152 个不该动、14 个该动）：**误操作率 0/152，漏清率 0/14**；另有 1 个被判 medium（无来源的安装包，只会被问）。注意：规则和案例都是我写的，这是回归测试，不是独立的外部评估。
- **演示**：`python -m sprite.demo_pressure OUT`（假探针+临时目录），`python -m sprite.render_demo` 出图。演示里 4 个陷阱（前台标签、播放中标签、未保存 Word、node 服务）和 9 个文件陷阱全部没动，撤销后清理项全部还原，用户切回浏览器后被挂起的标签进程恢复。
- **真实 Windows 上的限制**：进程相关需要 `pip install psutil`，而 idle 时长、是否有窗口、是否前台、是否在播放这些信息我还没在真实 Windows 上采集，所以现在**进程挂起实际上不会触发**（分类器拿不到这些字段时一律当 high）；文件类清理可用，但 `Zone.Identifier` 来源读取、挂起/收缩工作集的 ctypes 调用都没在真实 Windows 验证。

# 第三轮新增

## 价值闸（framework.py）
每个候选动作先估计 **价值**（用户秒数：缓解占比×严重度，或动作自带的 `value_s`；有“你迟早得自己做”的证据 `later` 则 ×1.5）与 **成本**（token 钱、风险、打扰），只有 价值≥最小值(20s) 且 ≥2×成本 才动手；琐碎动作（例如压力很大时只能清掉 100KB）会被跳过，所有估算都写进 `judgments_actions.jsonl`（`decision=skip_low_value / auto` 带 `value_s、cost_s、later`）。

## 分层 token 成本架构（tiers.py）
- **tier0**：纯本地代码/统计，随时开着、状态变化触发，0 token（轮询、规则判断、本地措辞都在这层）。
- **tier1**：可选本地小模型（`Router(local_model=...)`，如 Ollama），不花云端 token。
- **tier2**：云端模型（MiMo，`~/.config/ai-butler/mimo.env`），只在 ① 遇到**不认识的大文件类别**且价值够（≥120s）时分类一次；② 高价值话题（挑战/不同意/改口）润色。分类结论蒸馏进 `distilled_rules.json`，同签名的以后命中缓存 0 token；签名是抽象的（扩展名/目录名模式/名字模式/大小量级），不含用户名和路径。**模型的判定只能是 ask/high，永远不能是 safe**；要变 safe 只能靠你多次点同意。
- **硬预算**：`config.json` 的 `daily_tokens`(20000)、`daily_usd`(0.05)；超了降级为“保守不动/本地措辞”。每次调用记入 `tokens.jsonl`，`Meter.report()` 出分日报表。
- **模拟**（`python -m sprite.sim_tokens [--calibrate]`）：用真实 MiMo 校准每次调用的 token（分类 125 入/176 出，话术 289/142，一次“盯屏”轮询 1237/300），30 天、每天 192 次轮询、约 40 个事件、约 6 次说话：
  - “LLM 盯着一切”基线：约 **338,798 token/天**（约 $1.6/月，按假设单价 $0.10/$0.40 每百万 token）；
  - 分层架构：约 **836 token/天**（约 $0.006/月），约 **405 倍**更省；第一周 1192/天 → 最后一周 891/天（缓存规则生效，但长尾类别仍会出现，所以不会降到 0）；学到 59 条规则；预算压到 1500/天仍正常降级。
  - 注意：事件构成（25% 落在不认识类别、Zipf 分布）和价值分布是我假设的；“盯屏”基线每次轮询只估一次调用；事件判断的输入 token 按轮询的 70% 估算，未单独实测。

## 一行汇报
动作自带 `done_short`，汇报默认一行（≤40 字，如“电脑还卡。停了 4 个后台进程、清了 16 个缓存，可还原；剩 2 项要你定”），气泡里有“详情”按钮展开长版本。

## 长期约定学习 + 重复造轮子证据（通用机制，没有“开源优先守卫”）
“你反复提醒代理的同一件事”是一类潜在问题，“代理在重复造已有的轮子”是另一类证据；两者都进同一个学习器，落地走同一个带类型的动作。**“优先用开源”只是其中一条被推断出来的约定，不是写死的。**
1. **约定学习器**（`conventions.py`）：证据事件 = 你对代理/工具说的话与纠正（`--tell 项目路径 "话"` 或活动流里的 `instruction/correction`）、项目规则文件里已有的条目、任意检测器给的 `theme` 证据。判断“是不是约定”只看：像不像指令/偏好的话语形式、是否重复、是否跨天/跨会话（同一会话连说 6 遍只算 1 次）、是否只针对某个具体文件/行号（权重打 0.25 折）、有没有互相矛盾的说法（极性相反→都不落）、规则文件里是否已有、你是否撤销过。置信度 = 1−exp(−Σ权重)，≥0.6 才落地（3 次跨天提醒≈74%，2 次≈59%不够）。跨 ≥3 个项目都出现→全局约定，对还没有它的项目只“问”。
2. **重复造轮子证据提供者**（`reinvention.py` + `capability.py`）：描述来自文件自身（文件名/顶部注释/定义名），不含任何类别清单；体量≥60 行、写稳定、与项目本身业务耦合低（本项目模块导入占比≤30%）、不是薄封装/tests/vendor、项目本身不是做这件事的，才去查**可插拔的 `CapabilityIndex`**（`GitHubIndex` 真实；`FixtureIndex` 离线测试；可接 PyPI/npm/内部库），候选必须通过 `VerifierPolicy` 的**可核实事实**：许可证、没归档/fork、N 天内有更新、采用度、与要做的事的相关度；项目已依赖该候选则不算。它只产出证据事件，不直接落规则；一次核实过的证据权重 1.0（置信度≈63%），所以第一次发现就够落**项目级**规则，而两条模糊提醒不够。
3. **落地动作**（`persist.py`，类型化）：写进项目里**已存在**的各工具规则文件（AGENTS.md/CLAUDE.md/GEMINI.md/.cursorrules/.windsurfrules/copilot-instructions），都没有才新建 AGENTS.md；追加带标记块、带证据与置信度，必要时附带预检脚本；项目级 `safe/full`（字节级可还原，自动做并一句话告诉你），全局级 `medium`（只问）。撤销后同一条不再提。价值闸里“你已提醒过 N 次”算“迟早得自己做”的证据。
测试（`test_conventions.py`、`eval_all`）：同一套机制学到 4 条互不相干的约定（不提交密钥、改完先跑测试、提交信息用中文、优先复用现成库）并分别落进 AGENTS.md+CLAUDE.md；重复造轮子在 pdf 解析/csv diff 两个领域都出证据；陷阱（同会话重复、任务专用、自相矛盾、已有规则、只两次、疑问句、业务耦合、已依赖、薄封装、项目本身、tests、vendor、还在写、GPL/过期/低采用候选、索引离线）全部不动。局限：纯本地 n-gram 合并不了释义（“别造轮子”≈“先找现成的”），需要可选的 tier1/2 语义钩子（`semantic=`，已测试其接入，但没接真实模型）；GitHub 关键词搜索召回差，真实命中率没测。

## Windows 探针（winprobe.py）
分层降级：psutil（可选）→ ctypes（EnumWindows 窗口标题/可见/前台、IsHungAppWindow）→ `tasklist /v`；音频用可选的 pycaw，没装则为“未知”（此时浏览器后台标签要求空闲≥30 分钟而不是 15 分钟）。`CpuTracker` 在连续快照间比较 CPU 时间得出 `idle_s` / `busy_s`，只有观察够久才会声称空闲了多久。缺字段一律保守不动。以上均只在假后端下测试，**未在真实 Windows 验证**。

## 隔离区到期（quarantine.py + scenarios/more.py）
不是定时器：只有“隔离区变大或磁盘紧张”这个状态出现时才评估。条件：放了 ≥N 天（14）**并且**（可再生 或 副本仍逐字节一致）才自动永久清除；没有副本也不可再生的，合并成一个问题问你。

## 新增场景（全部只靠注册，见 scenarios/more.py）
