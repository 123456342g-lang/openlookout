# 小精灵现场演示（真实内存压力 + 真实进程挂起 + 沙箱文件清理）

**这是真的**：真实的内存探针（psutil/ctypes）、真实的内存告警阈值、真实的进程挂起（`NtSuspendProcess`，**只挂起、从不结束**），走真实的 GUI。
文件清理**只发生在沙箱** `E:\OpenLookout\sprite_sandbox\demo`（默认；除非你在 `demo_live.json` 里明确列出别的缓存目录）。
**真实 Windows 已验证**（2026-10-10，Windows + Python 3.11）：真实探针读到 251~254 个进程/内存/前台窗口；真实压力（可用 2.8GB < 阈值 3.1GB）下精灵自动隔离沙箱内 14 个有硬证据的文件并一行汇报、高风险/无证据项全部跳过不误动；14/14 撤销还原、11 个陷阱文件逐字节不变；`WinBackend` 真实挂起/恢复自产测试进程（journal 写入→清空）。

## 0. 准备（一次）
1. Python 3.10+（`python --version`），自带 tkinter。
2. `python -m pip install psutil`（强烈建议；没有它读不到进程命令行，精灵识别不了浏览器后台标签进程，就不会挂起任何进程）。可选 `pip install pycaw`（识别谁在出声；没装时“音频未知”，空闲门槛翻倍）。
3. 解压 `sprite_deploy.zip` 到 `E:\OpenLookout\src\openlookout\`（目录里要有 `sprite\demo_live\run_demo.bat`）。

## 1. 第一步：干跑预览（什么都不会动）
双击 `sprite\demo_live\dry_run_processes.bat`，等 75 秒。它列出：**如果现在内存告急，精灵会挂起哪些真实进程**，以及内存占用最大的 12 个进程各自为什么不动。结果也写在 `E:\OpenLookout\sprite_home\dry_run_processes.txt`。
列表是空的也正常（没有长时间空闲的后台标签）。看到不想动的进程，就先别 `--live`，告诉我。

## 2. 第二步：干跑模式看流程（不挂起任何进程）
1. 双击 `run_demo.bat`（默认干跑，沙箱自动铺好）。屏幕右下角出现小猫（可拖动）。**等约 2 分钟**让它先观察哪些进程一直空闲。
2. 双击 `trigger_memory_explosion.bat`：红色置顶小窗开始**真实占用内存**（给系统至少留 1.5GB；窗口上有“停止并立刻释放内存”按钮，Esc 也行；240 秒自动释放）。16GB 机器默认会吃掉约 10GB，要少吃：`trigger_memory_explosion.bat --mb 4000`（但要低于告警线才会触发：可用内存 < max(20%×总内存, 2.3GB)）。
3. **没有任何提问。** 只有内存真的低于告警线时，小猫才动手：先做回收量最大的，**一旦压力解除就停手**（没有压力 = 不清理、不出声，不会循环清缓存）。动完只说**一行**（例如“停了 3 个后台进程、清了 12 个缓存，可还原”），带 **撤销** 按钮（`详情` 看明细）。“【干跑·没真动】”表示进程没有真的被挂起，只记录“将会挂起谁”到 `demo_live.log`。
4. 沙箱里只有**有硬证据**的（缓存/临时文件、有逐字节相同副本的大旧文件）会被收进隔离区；**拿不准的**（查不到来源的旧安装包、模型猜测的大文件、名字不像副本的重复件）和**不可还原的**（永久删除）**一律不做，也不问**。点 **撤销** → 字节级还原（每条汇报各自有撤销）。
5. 点红窗的停止按钮。想重来：`reset_demo.bat`。

## 3. 第三步：真实挂起（`--live`）
1. 先打开 Chrome/Edge，开几个标签页（**别开会议/视频通话/下载/未提交的网页表单**），然后切到别的程序（例如放着 eat_memory 红窗/记事本），让浏览器后台标签闲置。
2. 双击 `run_demo_live.bat`，等约 2 分钟。
3. 双击 `trigger_memory_explosion.bat`。精灵会**真实挂起**空闲的浏览器后台标签进程并 `EmptyWorkingSet`，动完一行汇报；点“撤销”会恢复被挂起的进程（并还原对应沙箱文件）。
4. 你切回浏览器时，精灵会自动恢复被它挂起的浏览器进程（被挂起期间标签页会暂时冻住，这是正常的）。

## 4. 安全网（都已测试：Linux 真实 SIGSTOP/SIGCONT + Windows ctypes 调用序列 mock）
- 只挂起，代码里没有任何结束进程的调用（测试会扫描源码确认）。
- 永不碰：前台程序树、在出声的、标题带 `*`/未保存/无标题 的窗口、编辑器/IDE/终端/Python/本精灵及其启动者、系统与安全软件、有子进程的、资源管理器等（`procctl.DENY_NAMES` 硬黑名单 + 风险模型双重把关）。
- 数量上限 6 个、累计内存上限 4GB（`demo_live.json` 可调小）。
- **持久日志** `E:\OpenLookout\sprite_home\suspended.json`：先写日志再动手。
- 恢复手段（任何一个都行）：精灵里点“撤销”；`resume_all.bat`；`stop_demo.bat`（精灵退出时自动恢复）；精灵崩溃/被强杀 → **看门狗进程自动恢复**；下次启动精灵也会先恢复遗留的。PID 被复用时按创建时间核对，不会误碰别的进程。
- eat_memory：硬下限 1.5GB 可用，超时自动释放，进程被杀也由系统回收内存。

## 6. 诚实的说明
- **真实 Windows 已验证**（2026-10-10，Windows + Python 3.11.9 + psutil 7.2.2）：`dry_run_processes` 真实列出 251 进程/前台识别/12 个最大进程的拒绝理由（0 误判）；`live --no-gui` 干跑模式下真实压力（可用 2.8GB < 3.1GB 阈值）自动隔离沙箱 14 个有硬证据的文件（有副本大旧文件/超一天临时文件/浏览器缓存/旧安装包/包管理器缓存），高风险与无证据项全部跳过；一行汇报「清了 14 个缓存，可还原」；`stage_demo.check` 撤销后 all_restored=True、11 陷阱逐字节不变；`WinBackend` 对自产测试进程真实 `NtSuspendProcess`/`NtResumeProcess` 成功（journal 先写后清）。未覆盖：真实 GUI 冒泡截图（T3 已验证 GUI 本身）、200%+ 缩放（无硬件）。
- 为了演示，把“空闲 15/30 分钟”缩成约 1/2 分钟（`PROC_IDLE_SCALE=0.07`）、把“大文件”门槛从 500MB 降到 20MB；文件清理平时由磁盘压力触发，演示里绑在同一次内存告警上，方便一次触发看全流程。
- 浏览器后台标签是否算“空闲”取决于 CPU；没装 pycaw 时无法确认是否在出声（所以门槛翻倍），**别在 --live 演示时开着正在播放的标签**。
- 沙箱约占 280MB 磁盘；整个目录可随时删除。

## 7. 执行层（新）：代码 / 桌面 / 文档
除了清理，精灵有三类**声明式注册**的执行器（`sprite/executors.py`），遇到“要写代码 / 要操作桌面 / 要写文档”的问题由决策核心挑风险最低的那个，本地代码执行，**同样直接做、一行汇报、可撤销、不提问**：
- **代码**：先在沙箱副本里写入 + 编译 + 跑你指定的检查，通过才改真文件；改前备份，撤销=还原（你之后又改过则不覆盖，旧版另存 `.undo_restored`）。只能改你列出的目录。
- **桌面**：优先 API → 白名单 CLI → 文件操作；鼠标键盘只是最后手段，且只在你空闲 ≥2 分钟时用，每步检查，一有输入立刻中止并撤销已做的步骤；没有撤销办法的步骤整个任务不做。
- **文档**：只写**草稿**到固定目录（默认 `sprite_home\drafts`），不覆盖原件/旧草稿（重名加 `_v2`），没有发送能力（带收件人/发送字段的任务直接拒绝）；撤销=移入 `.trash`。
演示包里没有接这三类的现场演示，覆盖在 `test_executors.py`。
