# 主动感知：一体化算法与第一步

> 状态：**第一步已实现并跑通**（`tmp_surprise/surprise_lens.py`，输出 `tmp_surprise/surprise_report.md`）。
> 数据：`sprite_home/perceive/operations.jsonl` 快照 1,908 条事件，窗口 **10-12 07:17:12 → 08:45:46（88 分钟）**。

---

## 一、为什么现在没有"一体"的算法

系统今天把三件事当成三个互不相连的启发式：

| 环节 | 今天的实现 | 缺什么 |
|---|---|---|
| **看什么** | 每 2 秒抓全屏，画面变了就上传 | 没有**预期**，所以每一帧同样"有趣" |
| **要不要说** | 把当前帧丢给模型，模型自由裁量 | 没有**价值**，所以只能复述指标、旁白化 |
| **说了有没有用** | 三态全丢（`accepted` 丢弃、`timeout` 传 `lambda: None`、`rejected` 连按钮都没有） | 没有**闭环**，所以无从变好 |

**三者的病根是同一个：缺一个把"看"和"说"连起来的量。**

---

## 二、一体化形式（一个循环，四个量）

每个时刻 `t`：

```
x_t    情境（前台窗口、事件类型、停留时长、剪贴板、时间）
P      预期模型      x̂_t = P(x_t | x_{t-1})          ← 今天完全缺失
s_t    残差          s_t = -log2 P(x_t)              ← 注意力：只有残差值得深入看
C_t    候选动作      { 说一句洞察, 做一个小动作, 问一句/陪伴, 沉默 }
V(a)   价值          V(a) = 关联度 × 时效 × 可撤回性 − 打扰代价 − 错误代价
a_t    决策          argmax V(a)，且必须 V(a) > V(沉默)，否则沉默
r_t    结果          { accepted, ignored, rejected }  → 同时更新 P 与 V
```

**一体化的关键主张：感知与帮忙不是两件事，是同一个目标函数的两个投影。**

- **感知** = 在**状态空间**上分配注意力：只保留残差 `s_t`。
- **帮忙** = 在**动作空间**上分配干预：只保留正价值 `V(a) > V(沉默)`。
- 二者由**同一个结果闭环** `r_t` 驱动：同一条反馈既纠正"什么算异常"（P），也纠正"什么算有用"（V）。

没有 `P`，`s_t` 恒为常数，"值得看"无从计算 → 系统只能对所有帧一视同仁 → 输出必然是泛泛的指标话。
没有 `V`，`a_t` 无从比较 → 说话与沉默不可比 → 打扰。
没有 `r_t`，P 与 V 都停在初始值 → GUIDE.md 至今"仍是初始值"。

## 三、第一步：把缺失的那一项补上（已实现）

**范围**：只做 `P` 与 `s_t`。**离线、只读、不需要屏幕授权、不碰运行中的进程。**（约 2 小时工作量）

算法（第一版，故意最简单）：

```
s_t = -log2 P(app_t | app_{t-1})  -  log2 P(type_t)
```
- `P(app_t | app_{t-1})`：一阶马尔可夫 + 加 0.5 平滑，模型从同一段流水学出。
- `P(type_t)`：事件类型基线频率；`file_save` / `clipboard` / `file_open` 天然低频 → 天然高信息量。
- **上下文补齐**：`clipboard`/`file_save` 事件不带 `app` 字段，须用"当前聚焦窗口"补齐。
  （不做补齐的实测后果：Top5 全是 `app='?'`，把数据缺陷误判成行为异常——这一条是第一次运行后修正的。）

运行：

```powershell
& 'D:\python3.11\python.exe' 'E:\OpenLookout\tmp_surprise\surprise_lens.py'
# 快照需先做：operations.jsonl 正被 recorder 独占写入，须以 FileShare.ReadWrite 打开再复制
```

### 第一次运行就看到的四件事

1. **感知的 97.7% 只是"你在哪个窗口"**：`focus` 1,864 / 1,908；`file_save` 30、`clipboard` 13、`file_open` 1。
   而且 `windowsterminal` 一个应用占 **1,513 / 1,908（79%）**——感知几乎只剩"你在终端里"。
2. **88 分钟内系统只开口 3 次**；而这 3 次的时刻**全部**落在残差 Top25 里（秩 2 / 10 / 17）。
   → **它的开口时机不是随机的**（这是个正面信号），但**覆盖只有 3/25**，其余 22 个高残差时刻是沉默。
3. **残差最高的时刻是"用户真的动手了"**：`sublime_text` 的 `file_open`（s=13.19）、`cc-switch` 的剪贴板（9.51）、
   `explorer`/`windowsterminal` 的剪贴板（7.9 / 7.2）、`dsh desktop` 的 20 次 `file_save`。
   **这些时刻系统几乎全部沉默**——它有能力（`clipboard`/`file_save`/`form_edit` 记录器早就在跑），却没有把它们当作输入。
4. **它开口的 3 次内容都没有锚点**：一次是在用户用截图工具时插入"Downloads 里躺着两个 DSH 安装包，260MB 和 274"；
   一次是"早上那本《重启世界》翻到哪了"；一次是对磁盘数字的辩解。
   **时机对、内容空** —— 这正好指向第二个缺失项 `V`（价值闸），而不是 `P`。

### 为什么这是正确的第一步

- 它补的是**唯一缺失的载荷项** `P`，而不是加功能。
- 它**复用磁盘上已有的数据**：不新增采集、不申请权限、不打扰用户。
- 它的输出**直接就是**偏好抽取的语料（见 `DISCOVERY-LOOP.md` §3 L2/L3）：
  把"高残差 + 系统沉默"的时刻配上候选动作，就是那份给他划掉的清单。
- **可证伪**：若"高残差时刻"与"他觉得值得介入的时刻"不相关，则"主动感知 = 残差"这个假设在 2 小时内被否定，
  而不是在两个月后。**这是它最大的价值：把世界观赌注压缩成一次可当天验证的实验。**

## 四、第二、三步（顺序不可交换）

| 步 | 做什么 | 为什么在其后 | 完成判据 |
|---|---|---|---|
| **第二步** | 把 `s_t` 接成**离线 critic**：对历史每个高残差时刻生成 4 模态候选，用 `V` 初版打分 | 需要第一步的残差排序做输入 | 产出 N 个带候选的时刻，可交付"划掉" |
| **第三步** | 三态落库（`accepted`/`ignored`/`rejected`）→ `r_t` 进回路 | 需要第二步先定义"结果"的载体 | 能算出接受率；P 与 V 有更新依据 |
| 之后 | `V` 从 `r_t` 学出来（而不是手写常数） | 需要真实反馈样本 | 开口率降且接受率升 |

**硬约束**：`P`、`V` 都不许由模型在线自由裁量——它们必须是可复算的、有版本的量，
否则会退回到"把当前帧丢给模型让它自己看着办"，也就是今天的病。

## 五、这一步的诚实边界

- `s_t` 目前是**代理**（代理"值得看"），不是真值；真值只能由用户"划掉"给出。
- 一阶马尔可夫看不到语义（它不知道 `sublime_text` 里打开的是哪个文件），
  下一步应把 `title`/文件路径纳入上下文，或直接在有信息量的时刻抓一次截图（而非每 2 秒抓）。
- 本步只在**一台机器、88 分钟**的数据上成立；样本量与窗口都小，数字会漂移（项目正在运行）。
- 快照是只读副本；`operations.jsonl` 由 recorder 独占写入，读取必须用 `FileShare.ReadWrite`（`ReadAllLines` 直读会失败）。
