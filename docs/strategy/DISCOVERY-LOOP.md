# 发现回路：怎样做出「你还不知道想要的效果」

> 触发：项目负责人 2026-10-12 原话——**「这个看准时机主动帮忙或聊天的小精灵到底要怎么弄呢？我没法描述我想要的效果，因为这是未知的，很复杂，我需要你做出我没有意识到的想要的效果。」**
>
> 本卷是对这句话的直接回答。它不是又一份需求文档（那正好是这句话否定的东西），而是一个**能在你无法描述目标时逼近目标的机器**。
>
> 前置：`DEVELOPMENT-PLAN.md`（可信度方案）仍然成立且是本卷的地基——不是因为"该修 bug"，而是因为**没有结果标签就没有学习信号，本卷的核心机制会空转**。

---

## 0. 先把问题定性（这句话改变了什么）

| | 旧读法（仓库里所有文档的隐含假设） | 你这句话的实际含义 |
|---|---|---|
| 目标 | 已知，只是没实现好 | **未知**，而且不可描述 |
| 失败原因 | 提示词不够好 / 闸门没实现 / 指标没达标 | **结构上不可能被发现**（见 §1） |
| 解法 | 把要求写清楚 → 实现 → 验收 | 写不清楚 → 必须**搜** → 用你的反应当标签 |
| 你的角色 | 验收者 | **oracle（能认出、但说不出）** |

**关键判断：你说不出想要的效果，不代表它不存在或不可达；它代表目标函数只能通过"示例 + 反应"来逼近，而不能通过"描述 + 实现"来传递。**

这在外部已有人命名过：π-Bench（arXiv:2605.14678）把主动性单列为 **Proc** 指标，且实测**主动性高与任务完成度会背离**——即"看准时机"是一个独立、会互相冲突的轴，不是"完成度"的附属品。没有任何现成产品解决了它：微软 Recall 从公布退到 opt-in 再延期 11 个月上市，Copilot Vision 改成会话内显式共享并在 2026-03 进一步回退——**头部厂商是主动放弃"判断时机"这件事的**。

**这恰恰是这个项目唯一可能的护城河：全世界都没做"针对一个人的时机品味"，因为难、且不可通用。你的项目如果能做出来，做出来的东西不可能被通用产品替代。** 也正因此，它不能被"更好的提示词"解决。

## 1. 为什么现在的小精灵结构上做不到（三条，都可实测）

**① 只采样一次，从不搜索。**
现在的链路是"一帧画面 → 一次云端判断 → 一个结论"。它对"此刻有多少种可能有用的介入方式"**从不枚举**，所以**从不探索**。
你不可能从一个只会输出"提示词众数"的策略里，发现一个未被意识到的需求——它能想到的最好答案，就是"你的 C 盘快满了，要我清一下吗"。这不是模型笨，是**搜索空间被压成了一个点**。

**② 没有结果信号，回路是开的。**
| 状态 | 触发 | 现状 |
|---|---|---|
| accepted（点"好"） | `sprite/gui.py:198` | `sprite/proactive/live.py:252-257` 只 `hide()`，**丢弃** |
| timeout（气泡自消） | `gui.py:187,189` | `live.py:275` 传的是 **`lambda: None`**，**丢弃** |
| rejected（点"不用"） | — | `gui.py:193-200` **连按钮都不存在** |

**没有奖励的系统不可能朝一个未描述的目标移动。** 写入函数是现成的（`live.py:360 record_offer_result`），读取端也已就位（`help.py:111/109`）——缺的是三个调用点。**在本卷里，这三处不再是"埋点卫生"，而是唯一的训练数据来源。**

**③ 动作空间只有一个点，而且是你不想要的那个。**
`offers.jsonl` 292 条里 **284 条 `action=none`**、气泡中位 **121 字**（你要 60）、开口率 **33.5%**。它只会"说一句关于指标的话"。你自己的 `GUIDE.md` 把它点名为反面例子：**「别做指标触发的条件反射」**。

> 结论：**它不是在错误的答案上偏了一点，它是被设计成只能给一个答案。**

## 2. 原理：不可描述的效果只能被「搜」出来

要做出"你还不知道想要的效果"，需要同时具备三样东西——缺任一样都不可能：

| # | 要素 | 一句话 | 现状 |
|---|---|---|---|
| **①** | **候选空间** | 每一刻要生成 **k 个不同的**介入方式（而不是判断 1 个），且**必须包含"什么都不做"** | ❌ 不存在（只生成 1 个） |
| **②** | **结果标签** | 每个候选都要能拿到"你之后的反应/接下来的后果"作为标签 | ❌ 三态全丢，后果窗口也没记 |
| **③** | **偏好抽取** | 用**对比**而不是描述来问你的品味：不是"你想要什么"，而是"A、B、还是闭嘴？" | ❌ 从没做过 |

**第 ③ 项是整个问题的钥匙。** 你说不出想要的效果，但你**能认出它**——这是人类 tacit preference 的常态。所以正确的问法不是"请描述"，而是：

> **给出一组真实时刻，每个时刻列出"我们本可以做的 N 件事"，让你划掉错的。**

划掉不是噪音，划掉**就是规格**。20 个时刻 × 每个 30 秒就能产出一份用语言写不出来的偏好数据。这就是"做出你没有意识到的想要的效果"的工程化形式：**不是我去猜，而是我造一台把你认得出的东西榨成规格的机器。**

## 3. 五层发现回路

```
L0 仪器化 ──► L1 候选生成 ──► L2 离线 critic ──► L3 偏好抽取 ──► L4 效果库 ──► L5 在线闭环
 （近失+后果）   （k 个 × 4 模态）   （免你时间的搜索）    （你划掉）      （情境→介入）    （少说 + 实验）
```

**L0 仪器化**（最先做，唯一不可替代的输入）
- 记的不只是"开口了什么"，还要记 **近失（near-miss）**：它**想过但没说/被闸门拦下**的时刻。现在拦截计数落库 **0 条**（`session.py:37/105` 的自增只活在内 存），**而规格恰好藏在被拦下的那些里**。
- 记**后果窗口**：开口后 5–30 分钟内用户做了什么（是否立刻动手、是否重复同一操作、是否关掉窗口）。点击只是即时反应，后果才是"帮上了什么"。
- 接口：`live.py:252 / 275`、`gui.py:193-200` 加三态；`session.py:37/105` 的 `suppressed` 在 `session.close()`（`:187-188`）落盘；`offers.jsonl` 每行加 `candidates` 与 `gate_reason` 两个字段。

**L1 候选生成**（把"一个点"变成"一片空间"）
每一刻生成 k≈5–10 个候选，**必须跨四种模态**，且必须包含"沉默"：

| 模态 | 例子 | 为什么必须包含 |
|---|---|---|
| ① **说一句洞察** | "你这份文档 40 分钟没保存了" | 现在的唯一模态 |
| ② **做一个可撤销的小动作** | 直接挂起那个吃了 2G 的进程，然后一句话+撤销 | 你的 `GUIDE.md`：**「先做完再汇报，不要事前询问」** |
| ③ **问一句 / 闲聊 / 陪伴** | "连着弄了三小时了，歇会儿？" | 你说的是"**或者聊天**"——这里有独立的陪伴轴 |
| ④ **什么都不做** | — | **沉默必须是候选之一**，而不是被强制的默认 |

**②和③是当前系统完全没有的东西，也是最可能藏着"你想要但没意识到"的地方。**

**L2 离线 critic**（不花你时间就能搜索）
用已记录的历史（`perceive/operations.jsonl` 行为流水、`events.jsonl`、`offers/decisions`、截图索引）**重放**：对每个历史时刻生成候选，让 critic（规则 + LLM）预测"用户会怎么反应"，并给每个候选打分。
**这里就是 lookout/B 那条线从"想归档的副线"变成"主线必需件"的地方**：B 自带离线回填 + 惊喜门控 + 每日≤3 张卡的形态，正是一个**不需要屏幕授权、不需要你在线就能跑的搜索台**。
→ 产出：**候选语料**（真实时刻 + 多候选 + critic 排序）——这就是 L3 的素材。

**L3 偏好抽取**（唯一需要你参与的一层，且只要几分钟）
把候选语料做成**划掉清单**，两种形态（都要）：
- **回顾式**：一份 markdown，每个真实时刻列出 3–4 个候选，"划掉你不想要的"，保留你认得出的。→ 见 `_recon/06-candidate-moments.md`（正在生成）。
- **对照式**（信息量更高）：任选两个候选只问"哪个更接近你想要的"。说不出"想要什么"的人，几乎总能回答"这两个哪个更对"。
- **就地式**（最强 oracle）：气泡真的出现的那 5 秒，当场点"好/不用/换个说法"。此时你的反应是最真实的，因为它发生在情境里。

**L4 效果库**（把划掉变成治理行为）
活下来的东西固化成 **「情境模式 → 偏好介入方式」** 的条目库，每条带**证据计数**（几次、什么情境、你的反应）。
→ 这一步修的是第一轮卷宗诊断出的病根：**`GUIDE.md` 里写进去了画像，但它没有治理行为**（60 字要求落库后气泡反而更长）。**画像必须是 gate 读得懂的策略工件，不是散文。**
→ 新条目必须有证据才能进；与旧条目冲突时不是覆盖，而是**来问你**。

**L5 在线闭环**
少说；每次开口都是一次**预先登记了预期效果**的实验；事后测量后果；更新效果库。
这同时是 `DEVELOPMENT-PLAN.md` 里"价值闸"的正确形态：**闸门不裁定"这句话值不值得说"，它裁定"这个候选是否命中效果库里某条有正证据的情境模式"**——与第一轮卷宗的红线（模型不得在"值不值得说"上拥有最终裁定权）一致，但**把裁定依据从模型直觉换成了你的历史反应**。

## 4. 两种速度：为什么必须同时跑

| | 慢环（离线） | 快环（就地） |
|---|---|---|
| 输入 | 已记录的行为流水 | 正在发生的一刻 |
| 你的成本 | 一次性 20–40 分钟（划掉） | 每次 5 秒（点一下） |
| 产出 | 候选空间 + critic | 最真实的标签 |
| 需要屏幕授权 | 不需要 | 需要 |
| 什么时候用 | 现在就能开始，先把空间铺开 | 空间收窄到 10 个以内之后再上 |

**关键：先跑慢环。** 它是唯一在"你还不知道自己想要什么"和"我们还没有可信的实时链路"这两件事同时成立时还能推进的东西。而且它**完全不需要新的屏幕授权**——这也顺带绕开了市场卷发现的隐私死局。

## 5. 效果假设（喂给候选生成器的种子，**不是结论**）

你说"做出我没意识到的效果"，所以我给出具体猜测。它们是**送进 L1 去被验证/被划掉的种子**，不是被我写死的需求。每条都从你自己的行为里长出，每条都可被你的一个划掉杀死。

| # | 假设 | 依据 | 如果成立，它长什么样 |
|---|---|---|---|
| **H1** | **"做完再说"比"问要不要做"更接近你要的** | 你的 `GUIDE.md`：「先做完再汇报，不要事前询问」；现在 284/292 是 `action=none` | 小精灵**多数时候在动手**（挂着"撤销"），只在少数时候问。现在正好相反 |
| **H2** | **真正有用的是"意图漂移"提醒，不是"资源告警"** | 你点名「别做指标触发的条件反射」；而现有气泡几乎全是磁盘/内存 | "这件事平时 30 分钟，今天已经 3 小时了——卡在哪？" |
| **H3** | **你要的是"连续性"，不是"洞察"** | `operations.jsonl` 全量记录了你的操作；仓库里没有任何跨天记忆 | "上周三你卡在同一个地方，后来用 X 绕过去了" ——**认出但从未被要求过的能力** |
| **H4** | **陪伴是独立模态，需要单独的时机模型** | 你原话「主动帮忙**或聊天**」；现有系统把一切都做成"提议" | 深夜/长时间独处/连续失败的场合，一句低风险的人话，而不是一条任务 |
| **H5** | **最有价值的时刻是"你正准备做一件你会后悔的事"** | 现在有 `clipboard`/`form_edit`/`file_save` 的观察能力，却完全没有用在这上面 | 粘贴疑似密钥、覆盖同名文件、把没保存的东西关掉——**一次正确的沉默的伸手**，胜过一百条磁盘提醒 |

**注意 H3/H5：它们是"你没有意识到想要"的最强候选，因为现有系统的动作空间里根本没有它们的位置。** 这也说明为什么光调提示词没用——**不在动作空间里的东西，再好的提示词也生成不出来。**

## 6. 谁当老师：三种 oracle 的性价比

| oracle | 成本 | 信号质量 | 何时用 |
|---|---|---|---|
| **离线重放 + critic** | 零（不需要你） | 中（会系统性偏乐观） | 现在 |
| **回顾式划掉** | 20–40 分钟一次性 | 中高（脱离情境，但便宜） | 现在 |
| **就地点击** | 每次 5 秒 | **最高**（发生在情境里） | 空间收窄后 |
| **Wizard-of-Oz（人肉当大脑）** | 需要一个"人"顶着看屏幕 1–3 天 | **最高，且能发现完全没想到的东西** | 如果前三种收敛不了，这是最后的重锤 |

**Wizard-of-Oz 值得单列**：让一个真人（我 / 一个 teammate）直接当小精灵的"判断大脑"，接在现有屏幕流后面，只在真的值得说话时说话；你的反应就是标签。**这是"做出你未意识到的效果"最快的一条路**，因为发现未知未知靠的不是分析而是**试错+你的即时反应**。代价是它要我的时间，不要你的（除了当 oracle）。

## 8. 判据：什么情况说明这条路也不成立

诚实边界——这条路线可能失败，用这些判据早发现：

| 观察 | 含义 | 动作 |
|---|---|---|
| 划掉 3 轮后仍无任何可学模式（你划掉的候选与保留的候选没有共同特征） | 效果对**此刻的你**不可判定 | 退到"用户显式命令的工具"形态（B 逃生通道） |
| 你能认出好候选，但**发生时**的真实反应与回顾式划掉系统性相反 | 品味是情境性的，回顾式 oracle 无效 | 只信就地 oracle，上 Wizard-of-Oz |
| 效果好但**必须常驻截屏**才做得出 | 撞上市场卷的隐私死局 | 退回慢环（离线痕迹），放弃实时主动 |
| 开口率降不下来，或降下来但接受率不升 | 闸门砍错了（砍掉了该说的） | 回看被拦样本（这就是为什么要记近失） |
| 每次介入都需要模型看全屏原生像素 | 成本/延迟/隐私三线崩 | 先做本地摘要，再谈实时 |

## 10. 一句话

> **你要的不是一个更聪明的小精灵，是一台能把你"认得出但说不出"的品味变成规格的机器。**
> 它由三样东西组成：**把动作空间铺开（候选）、把你的反应变成标签（结果）、用对比来问你（抽取）。**
> 现在这三样一样都没有——所以它不是偏了，是**还站在原点上**。
