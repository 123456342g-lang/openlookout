## 怎么用这份清单

1. 一条一条看，**一条大约 10 秒**。你的任务不是打分，是**划掉**：留下你要的那个时刻和那个做法，其余全划掉。
2. 每条末尾都有一行 `**划掉：** ____`。保留哪个就写哪个字母（写 `A`），只要一部分就写 `keep A, kill B,C`，整条都不要就写 `全划掉`。
3. A/B/C/D 里**总有一个是「静默」**。它不是凑数的：很多时刻的正确答案就是闭嘴，那也请明确写出来——「闭嘴」和「开口」一样是规格。
4. 每条都压成四行：时间 / 当时屏幕上是啥 / 系统当时做了什么 / 它本来可以做的 4–5 个选择（洞察·动作·搭话·静默，顺序固定）。一眼认出「对，就是这个时刻」，就够。
5. 候选后面的 `[critic x/3]` 是**我的预判分**，不是裁决。3 = 我认为你会认；2 = 有可能；1 = 弱；0 = 大概率招烦。**我故意留了几条 0 分做对照**，别因为看见 0 就跳过。
6. `【实测】` = 账本里逐字可查；`【推断】` = 我推的，可能是错的。请**重点看所有【推断】**，那是我最容易骗到你的地方。
7. 每条候选都写了 `期望`：它赌的是「改掉你接下来 30 分钟里的什么」。如果那个效果对你没意义，那就别要这个候选，别管它 critic 几分。
8. 机器可读版在 `06-candidates.jsonl`（一行一时刻，含 `candidates[]` 与 `keep:null`）。你划完，可以用脚本把 `keep` 填回去——这就是 §3 说的 L3「偏好抽取」的原料。
9. 这份清单里**没有编造的时刻**。只有 100 条（要求 80–120 条）是因为我宁可少而真：账本里找不到证据的「好想法」，我一条都没写。
10. 数据是活的（多个 python 进程在写）。行号以 2026-10-12 08:55 那次读数为准；**数字会漂，请以「时刻」为准，不要以数字为准**。
