# 主动助手产品策略研究（桌面持续观察场景）

> 目的：为 OpenLookout 选择可收缩、可验证的产品切口。本文只使用公开资料与项目已有说明；不读取用户运行数据或密钥。文中“事实”指可在公开页面核对的产品声明；“推断”是基于这些声明的产品判断；“未知”表示没有足够证据，不把测试数量当作用户价值。

## 2. 常见失败模式

以下为公开事件与产品形态支持的**推断**，不是对任何单一产品的内部数据断言：

1. **价值承诺过宽**： “记住一切/能做任何事”很难让用户知道何时值得等待，也难定义完成标准；首次惊艳不等于日常留存。
2. **主动打扰成本非线性**：误报一次会降低后续每次提示的可信度；桌面常驻产品比聊天机器人更容易被静音或卸载。
3. **观察≠理解**：OCR、窗口标题或截图只能提供证据，不能可靠推断意图、情绪、权限和“现在是否方便”。
4. **执行风险高于建议风险**：跨应用点击、发送、删除、进程控制等不可逆动作一旦误触，损失远大于漏提醒；必须分离“观察/提议/执行”。
5. **隐私与合规是产品功能**：持续录屏/录音会捕获密码、健康、私人对话和他人信息；云端传输、团队共享、保留期限若不透明，用户会拒绝授权。Limitless 的产品收缩与 Recall 争议说明，采集能力并不自动转化为可持续业务。
6. **资源和成本失控**：Screenpipe 公开给出持续采集的 CPU、RAM 量级；全天候多模态推理还会叠加存储和模型费用。频率、分辨率、模型档位必须成为产品策略，而非实现细节。
7. **反馈被误当命令**：用户说“帮我弄快点”未必授权执行；把一次拒绝简单改写后重提会造成骚扰。

## 3. OpenLookout 的收缩路径（建议）

### 3.1 先选“高频×高价值×可验证”的单一机会

优先级判据：

- **高频**：每周至少数次、可由屏幕时序事实识别（长时间停滞、阶段完成、反复来回）。
- **高价值**：节省明确时间或避免可感知损失（例如忘记提交、卡在错误配置、会议后遗漏下一步）。
- **可验证**：用户能在 1–5 分钟内回答“有用/没用”，并可记录接受、拒绝、撤销和完成，而不是用模型自评。
- **低风险**：第一阶段只做只读、草稿、导航或提醒；不发送、不删除、不结束前台程序。

建议首个切口：**“阶段性卡住/完成后的下一步提醒”**（写代码、写报告、整理桌面各一套明确规则），每轮最多一句；用户点“好的”后生成草稿或打开相关位置，仍由用户最终确认。不要同时承诺全屏幕管家、健康教练、自动整理和跨应用执行。

### 3.2 主动 agent 与被动 agent 分工

- **主动层（默认安静）**：只判断“现在是否值得打断”，输出 quiet / companion / offer；依据画面变化、停留时长、阶段信号、近期接受/拒绝记忆。主动层无权直接执行外部动作。
- **被动层（按需召回）**：用户主动提问时再搜索历史、解释依据、生成草稿或列出选项；可使用更高成本模型，因为触发由用户承担。
- **执行层（显式同意后）**：每个动作有范围、预览、撤回日志和结果回显；高风险动作需二次确认。三层之间通过结构化事件传递，不共享“隐式自主权”。

## 4. 核心用户循环与完成标准

1. **观察**：本地采集当前帧和通用时序事实；默认不保存原图到云端。
2. **判定**：模型先回答“是否有明确帮助机会”；不确定即 quiet。去重同一 topic，尊重近期拒绝。
3. **交付**：companion（无按钮）或 offer（单一、具体、可预览）。文案说明依据和预期结果，避免拟人化夸大。
4. **同意**：用户点“好的”才进入执行；“不用”记录 topic 冷却，不换措辞重提。
5. **执行与回显**：执行前写撤回计划；完成后给出实际结果、耗时、失败原因和“撤销”入口。
6. **学习**：只更新与该 topic 相关的偏好（频率、时机、是否需要预览），不把一次反馈固化为永久画像。

完成标准（每个机会必须预先定义）：

- 提醒完成：用户在 10 分钟内采取相关动作，且未立即撤销/投诉；
- 草稿完成：草稿生成并由用户显式保存或发送（发送本身仍需用户确认）；
- 自动动作完成：动作结果可观测、可回滚，且无安全策略违规。

## 5. 信任、隐私与退出设计

- **本地优先、最小化上传**：屏幕帧只在本机和已配置模型服务之间流动；默认不做云端长期录像。对每轮发送内容显示“当前帧/摘要/系统事实”范围。
- **可见开关**：总暂停、按应用/窗口排除、麦克风独立开关、立即删除最近 N 分钟、导出 GUIDE/历史；暂停状态在 UI 常驻显示。
- **敏感区保护**：密码管理器、银行、医疗、私人聊天默认排除；允许用户添加规则。多人会议录音需明确提示和本地合规检查。
- **权限分级**：观察、提议、草稿、执行四级权限；高风险动作永不由隐式反馈授权。
- **审计与撤回**：每次 offer/同意/执行/撤销写本地时间线，用户可查看“为什么现在提醒”。撤销优先于继续自动化。
- **诚实沟通**：区分“看到的证据”“模型推断”“未知”；不声称理解情绪、意图或持续记忆超出实际保留范围。

## 6. 如何验证而不自欺

- 先做 2–4 周单人试用或小规模可控试验，按机会类型记录曝光、接受、完成、撤销、静音和延迟反馈；不把“模型调用成功”当价值。
- 关键指标：**每次打扰净价值**（接受完成率 − 拒绝/静音成本）、误报率、从 offer 到完成的时间、撤销率、每用户每日提示上限、单位完成成本。
- 分层比较主动与被动：同一机会一组仅被动召回，一组允许主动 offer；若主动组未显著减少完成时间或错误，就收缩主动频率。
- 设置停止条件：连续一周净价值为负、撤销率超阈值、或出现一次不可逆安全事件，立即关闭该场景而非继续调 prompt。
- 所有结论标注样本量、场景和时间窗；项目已有“40 个测试通过”只能证明机制回归，不代表真实用户价值。

## 7. 结论

OpenLookout 应把“持续观察”当作昂贵的感知基础设施，而不是卖点本身；产品卖点应是少量、可验证、可撤回的帮助。第一阶段宁可只覆盖一个低风险场景并保持大多数轮次 quiet，也不要复制“记住一切/替你做任何事”的承诺。公开产品的收缩、争议和资源成本共同表明：**边界、退出和证据链本身就是核心体验。**
