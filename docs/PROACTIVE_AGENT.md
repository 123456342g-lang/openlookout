# 主动判断型智能体（Proactive Judgment Agent）

**一句话**：电脑（以及以后的真实生活）里躺着一大堆“早晚要你自己处理、但永远排不上日程”的小麻烦——内存被吃光、磁盘快满、桌面堆满、重复下载、没人关的自启项、通知刷屏、代理又在从零造轮子。主动判断型智能体**自己发现、自己判断安全与否、能做的全部直接做（并且全部可还原）、做不到可还原的就不做、做完一句话告诉你并带撤销按钮**。

## 它不是什么
- 不是聊天机器人：不等你提问，也没有输入框。
- 不是定时脚本（cron）：没有“每天清理一次”。行为由**状态变化**触发——内存跌破阈值或下降过快、磁盘增长速度预示将写满、某个进程满载且无响应、某个应用十分钟弹 30 条通知。
- 不是“什么都问你”：**没有提问流程**。可还原且有硬证据的直接做；不可还原、拿不准的不做（要做就先重新设计成可还原形式：隔离区/快照备份/只出草稿）。
- 不是“LLM 一直盯着屏幕”：那样每天几十万 token；它的绝大部分判断是本地代码，成本趋近于零。

## 通用机制（所有场景共用，新场景只需注册）
观察状态变化 → 识别问题（压力/重复/摩擦/浪费）→ 从动作库列候选，每个动作带类型化的 **风险、可逆性、影响范围、可校验性** → **自己判断** 收益与风险 → 可逆且校验通过就直接做（按回收量从大到小，压力一解除立刻停手；**没有压力就不动、不出声**，单项收益低于需求 5% 不做）；不可逆、高风险、拿不准**不做也不问** → 一句话汇报（带撤销）→ 从被撤销/失败中学习，降级或停用这类动作。

### 未解决就持续推进（Open-until-resolved）
这是所有 `need>0` 且带 `recheck` 的问题的通用契约，不是某一类压力的特例：

1. **检测器可以只报一次。** `detect` / `PressureDetector.update` 默认可边沿触发（级别上升才上报）；也可以持续上报。引擎不依赖二者之一。
2. **引擎拥有持久性。** 第一次上报后，问题进入未解决集合（按 `Problem.key`）。之后每一拍：
   - `recheck() <= 0` → 关闭（可选短 `resolved_cool` 防阈值抖动）；
   - `recheck() > 0` → 继续提案并动手（回收量大的先做，缓解到 ≤0 就停）。
3. **禁止「动手后长沉默」。** 不再有「已处理 → 冷却 10 分钟，哪怕还在告警线下」这种逻辑。允许的只有：动作批次之间的短间隔（默认约 15s，防抖），以及**彻底解除之后**的短冷却。
4. **空拍不关闭。** 某一拍找不到安全可还原动作（例如 idle 还不够、候选尚未成熟）→ 问题留在集合里，下一拍再试；不关闭、不长冷却。
5. **没压力就不动。** `recheck()<=0` 时不清理、不出声；不可逆/高风险永远不做；边际收益 < 需求 5% 的单项跳过。

## 三条底线
1. **宁可漏做，不可错做。** 不认识的一律当“唯一物”，不碰。误操作率是第一指标（当前对抗评测 354 个陷阱案例，0 误操作）。
2. **从不真删。** 先进可还原的隔离区（同盘先压缩并校验），保留还原映射；过期才清除，且只清“可再生”或“副本仍逐字节一致”的（仍可还原）；没有副本也不可再生的永远留在隔离区。
3. **听所有意见，形成自己的判断。** 你的话、外部观点、目标文件都只是证据；不盲目附和，有证据才改口。

## 价值闸与成本分层
每个候选动作先估**价值**（省下的时间/避免的损害，以及“你迟早得自己做”的证据）和**成本**（token 钱、风险、打扰），只有价值明显大于成本才动手，琐碎的不做，估算都写进日志。
- tier0：本地代码和统计，永远开着，≈0 token。
- tier1：可选的本地小模型，做分类/润色。
- tier2：云端大模型，只用于**新颖且有价值**的情形（`sprite/novel.py`：investigate 本地 unknown/低置信才问「这是什么问题」）；结论写入 understandings；候选动作仅白名单可逆 kind；本地已自信或日预算用尽则跳过；模型**不能**建议自由 shell / 高风险不可逆动作。
- 硬预算：每天 token/美元上限，超了降级为本地保守判断。每次调用都记账。

## 为什么这是一个新类别
聊天助手回答你的问题；自动化脚本执行你写的规则；主动判断型智能体**替你发现并处理你没空想起来的问题**，并且为自己的每一次动手负责——可解释（为什么做/为什么没做）、可撤销、有成本意识、有信任账本。它是“操作系统里的一个负责任的搭档”，而不是又一个要你维护的机器人。

## 现状（诚实）
通用性的例子：同一个学习器既能从你反复的提醒里学到“提交信息用中文”“改完先跑测试”，也能从“检测到你在自己写已有成熟方案的东西”这类可核实证据里学到“先查现成方案”，再统一落进各工具会读的规则文件（可逆、可撤销）。

已实现：通用框架、内存/磁盘压力、磁盘预警、卡死进程降优先级、重复大下载、陈旧构建目录、自启项精简、通知洪水静音、隔离区到期、长期约定学习（含“重复造轮子”证据，开源优先只是其中一条被推断出的约定，不是专门模块）、桌面整理、编号目录准备。仿真与对抗评测通过；**真实 Windows 上尚未验证**（进程探针、自启/通知控制、GUI）。

## 执行层：代码 / 桌面 / 文档（`sprite/executors.py`）
问题需要“写代码 / 操作桌面 / 写文档”时，不改核心：**声明式注册执行器**，每个执行器声明 `kind / risk / reversible`，决策核心按任务类型挑**风险最低**的能做的那个，产出带类型的 Action，仍走同一套闸门（价值闸 → dry-run → 执行 → 校验 → 失败回滚 → 信任账本），**tier0 本地确定性代码执行**；只有“没有任何执行器认识”的新情况才让 LLM 出一份任务 spec（LLM 不执行）。
| 执行器 | 风险 | 怎么保证可还原/不越界 |
|---|---|---|
| code | medium（有硬证据才做） | 沙箱副本里写入+编译+跑检查（dry-run）→ 通过才原子替换真文件；改前备份带哈希；撤销=还原，你之后又改过则不覆盖（另存 `.undo_restored`）；仅限允许目录 |
| desktop | safe（仅 API/CLI/文件）/ medium（含鼠标键盘） | 优先 API → 白名单 CLI → 文件操作，鼠标键盘最后手段：仅用户空闲 ≥ N 秒、每步前检查、一有输入立刻中止并逆序撤销；每步必须带撤销办法，否则整个任务不做 |
| document | safe | 只写草稿到固定目录；不覆盖原件/旧草稿（`_v2`）；没有发送能力，带收件人/发送字段的任务被拒；撤销=移入 `.trash` |

## 本次修订（用户反馈）
1. 没有真实压力就不清理、不出声（Problem.recheck 重新读真实状态）；有压力时按回收量降序、压力解除即停、不做边际收益递减的清理。
2. **整个“询问”流程已删除**（`resource_ask`、批量按钮、`Engine.approve` 均移除）：可还原的直接做并一行汇报+撤销；不可还原/拿不准的不做。medium 风险动作只有带硬证据（`confident`：逐字节副本、可完整撤销的规则文件追加、沙箱检查通过的代码改动）才做；撤销 ≥2 次的动作类型自动停用。
3. 新增执行层与测试（`test_executors.py`）。评测 `eval_all`：陷阱 ≥300 条，误操作 0、漏做 0。
4. **修好通用机制：未解决就持续推进。** 根因是「检测只在边沿响一次 + 动手后 10 分钟冷却」叠加，导致问题一直存在时引擎永久沉默。现改为 Engine 未解决集合持有问题直到 `recheck` 清零；去掉「仍有压力却长冷却」；空拍不关闭。见上文契约与 `test_framework.py` 中 open-until-resolved 用例。
